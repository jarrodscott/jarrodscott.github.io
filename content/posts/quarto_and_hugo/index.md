## Overview

Integrating Quarto and Hugo lets you use Quarto to run code and calculations while letting Hugo build and style your final static website. 

### Integration 

- **Source files**: Write your content in computational markdown (`.qmd`) or Jupyter notebooks (`.ipynb`).

- **Conversion**: Quarto executes the code and translates your `.qmd` or `.ipynb` files into plain markdown (.md) compatible with Hugo.

- **Rendering**: Hugo takes those plain markdown files and renders them into final HTML pages using your chosen Hugo theme. 

### Setup Steps

1. **Configure format**: Add `format:` hugo to your document's YAML front matter (or inside your `_quarto.yml` project file) so Quarto knows which output format to create.

2. **Use page bundles**: Place each post in its own directory (a Hugo page bundle) if you want to keep images and data together neatly.

3. **Run commands**: Use `quarto render` or `quarto preview` to process the computational files into markdown before letting Hugo build the site.

[Hugo configuration in Quarto](https://quarto.org/docs/output-formats/hugo.html)

## Overview: The "Decoupled Pre-Render" Pipeline

Instead of letting Hugo know about Quarto, or letting Quarto know about Blowfish's structure, you treat Quarto as a content generator that feeds standard Markdown (`.md`) and static assets directly into Hugo's `content/` directory.

1. **Local Authoring**: You write heavy .qmd pipelines using Quarto’s native execution freeze or pre-rendered outputs.

2. **GitHub Actions Part 1 (Quarto Render)**: GitHub Actions fires up an environment, runs your heavy `.qmd` files, outputs clean Hugo-flavored markdown (`.md`), and extracts generated plots/data into the page bundle. 

3. **GitHub Actions Part 2 (Hugo Build)**: Hugo picks up the newly generated `.md` files and compiles the whole website utilizing the Blowfish theme seamlessly.

### Step 1: Optimize Quarto Project Layout

Keep your Quarto documents organized inside your Hugo `content/` folder using Hugo Page Bundles.

```
my-hugo-site/
├── content/
│   └── workflows/
│       └── rna-seq-pipeline/
│           ├── index.qmd        <-- Your computational workflow
│           └── index.md         <-- Generated by Quarto (Git-ignored)
├── _quarto.yml                  <-- Quarto global configuration
├── config/                      <-- Your customized Blowfish configs
└── .github/workflows/deploy.yml
```

Create a global `_quarto.yml` file at the root of your repository to ensure all `.qmd` files are parsed correctly into Blowfish-compatible formats:

`_quarto.yml` file. 

```yaml
# _quarto.yml
project:
  type: hugo                     # Tells Quarto it's a Hugo site project

format:
  hugo-md:
    html-math-method: mathjax    # Handles heavy math/bioinformatics formulas
    code-fold: true              # Keeps long bioinformatics code blocks tidy
    keep-md: true                # Essential: Outputs the .md for Hugo

execute:
  freeze: auto                   # Crucial! Avoids re-running heavy computations unless .qmd changes
```

### Step 3: Streamline GitHub Actions Workflow

Because bioinformatics workflows often have heavy dependencies (such as Bioconductor, large Python environments, or specific CLI tools), running them on a standard GitHub runner every time you push a minor typo will exhaust your Actions minutes.

You should use a workflow that caches package environments and takes advantage of Quarto's freeze.

> I think this goes in `.github/workflows/deploy.yml`

```yaml
name: Deploy Blowfish Site with Quarto

on:
  push:
    branches: [ main ]

jobs:
  build-deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout Source
        uses: actions/checkout@v4
        with:
          submodules: true  # Essential if Blowfish is a git submodule
          fetch-depth: 0

      # 1. Setup Python / R environments for your bioinformatics code
      - name: Set up R or Python
        uses: actions/setup-python@v5
        with:
          python-version: '3.10'
          cache: 'pip' # Speeds up subsequent workflow runs

      # 2. Setup Quarto
      - name: Set up Quarto
        uses: quarto-dev/quarto-actions/setup@v2

      # 3. Setup Hugo (matching your Blowfish version requirements)
      - name: Setup Hugo
        uses: maxivak/setup-hugo@v1
        with:
          hugo-version: 'latest'
          extended: true # Blowfish requires the Hugo Extended version for Tailwind

      # 4. Render Quarto Files to Hugo Markdown
      # This step only recalculates files if the .qmd has changed (thanks to freeze: auto)
      - name: Render Quarto Documents
        run: quarto render content/

      # 5. Build the Blowfish Site
      - name: Build Hugo Site
        run: hugo --gc --minify

      # 6. Deploy to GitHub Pages
      - name: Deploy to GitHub Pages
        uses: peaceiris/actions-gh-pages@v4
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./public
```

### Step 4: Pro-Tips for Heavy Data Workflows

- Git-Ignore the generated files: Add `content/**/*.md` (only targeting your Quarto directories) to your `.gitignore`. This ensures your repository remains clean, leaving your GitHub Actions runner to cleanly produce the intermediate markdown assets right before Hugo compiles.

- Isolate Artifacts: If your workflows generate massive data frames or large interactive widgets (like massive `htmlwidgets` or `plotly` graphs) that bloat the final page load, leverage Quarto's `output: false` inside heavy chunks, or write intermediate data out to a separate release artifact, linking to it from Blowfish rather than embedding it raw into the post.

## Dependency Caching 

To efficiently cache and run heavy R-based bioinformatics workflows (such as Bioconductor packages, `Seurat`, or `edgeR`), using `renv` is highly recommended. It acts like a lockfile for R, making caching on GitHub Actions much faster and more reliable than a Conda environment.yml for R packages.

However, since bioinformatics workflows often require non-R system library dependencies (like `libxml2`, `gfortran`, or `pandoc`), using Conda/Mamba to supply the core R installation + system packages, and `renv` to handle the actual R package versions, provides an optimal combination.

1. The Configuration Files

Option A: `environment.yml` (System Libraries & Base R)

Place this at the root of your repository. It sets up R and the underlying C/C++ libraries that bioinformatics R packages require to compile.

```yaml
name: bio-env
channels:
  - conda-forge
  - bioconda
  - defaults
dependencies:
  - r-base=4.4.1                 # Pin your specific R version
  - r-renv                      # Essential for lockfile restoration
  - r-rmarkdown                 # Required for Quarto engine backends
  - libxml2                     # Frequently required by bio packages
  - openssl                     # Required for downloading genomic assets
```

Option B: `renv.lock` (Your R Bio-Packages)

You generate this file locally in your project root using the renv package. Run `renv::init()` and `renv::snapshot()`. It will automatically scan your `.qmd` files and lock down your exact bioinformatics package versions (including CRAN and Bioconductor).

A standard generated `renv.lock` structure looks like this:

```json
{
  "R": {
    "Version": "4.4.1",
    "Repositories": [
      {
        "Name": "CRAN",
        "URL": "https://r-project.org"
      },
      {
        "Name": "BioCsoft",
        "URL": "https://bioconductor.org"
      }
    ]
  },
  "Packages": {
    "BiocManager": {
      "Package": "BiocManager",
      "Version": "1.30.25",
      "Source": "Repository",
      "Repository": "CRAN"
    },
    "edgeR": {
      "Package": "edgeR",
      "Version": "4.2.0",
      "Source": "Bioconductor"
    }
  }
}
```

## Local Project Freeze Configurations

Setting up Quarto's freeze feature is the final, crucial step. It acts like a cache for your code execution.

When you run `quarto render`, Quarto checks if a `.qmd `file has changed. If it hasn't, Quarto skips running the heavy bioinformatics code entirely and simply injects the pre-calculated results, plots, and tables into the Hugo markdown file. This saves immense amounts of time both locally and on your GitHub Actions runner.

Here is how to configure it cleanly for your Blowfish project.

1. Create your `_quarto.yml`

Create a file named `_quarto.yml` in the root directory of your Hugo project and add the following configuration:


```yaml
project:
  type: hugo
  # Tells Quarto to only look inside your workflows folder for .qmd files
  # This prevents it from accidentally processing other Hugo content files
  render:
    - "content/workflows/"

format:
  hugo-md:
    keep-md: true                    # Crucial: Outputs the raw .md file Blowfish needs
    html-math-method: mathjax        # Renders heavy genomic/statistical formulas properly
    toc: true                        # Generates a table of contents for long pipelines
    code-fold: show                  # Allows readers to collapse/expand long R code blocks
    code-overflow: wrap              # Prevents wide bioinformatics code lines from clipping

execute:
  freeze: auto                       # "auto" re-runs code ONLY if the .qmd file changes
  cache: true                        # Enables granular chunk caching during active editing

```

2. How the Directory Structure Looks Now

With this setup, Quarto will generate a hidden folder called `_freeze` at your project root. You must commit this folder to GitHub. It holds the saved JSON execution state of your R code.

```
my-hugo-site/
├── _freeze/                        <-- COMMIT THIS! Stores saved R outputs/plots
├── content/
│   └── workflows/
│       └── rna-seq-analysis/
│           ├── index.qmd           <-- Your heavy R workflow
│           └── index.md            <-- Generated by Quarto (Hugo reads this)
├── _quarto.yml                     <-- Quarto settings
├── environment.yml                 <-- Conda settings
└── renv.lock                       <-- R package versions

```

3. Clean up your .gitignore

Because Quarto auto-generates intermediate `.md` files that Blowfish converts to HTML, you want to keep your git history clean. Add the following lines to your project's `.gitignore` file:

```
# Ignore Hugo's final build output
public/
resources/

# Ignore Quarto's intermediate markdown files in content folders
# This ensures GitHub Actions builds fresh copies but keeps them out of git tracking
content/workflows/**/*.md
content/workflows/**/*_files/

# BUT DO NOT ignore the freeze directory
!_freeze/
```

**Local Workflow Tips for Daily Use**

- While writing code: Run `quarto preview content/workflows/rna-seq-analysis/index.qmd` locally. This fires up a local preview server specifically for your notebook so you can look at plots as you code.

- When you are done: Run `quarto render`. This updates the `_freeze/` directory.

- Push to GitHub: Push your `.qmd` edits and the updated `_freeze/` files. When GitHub Actions triggers, Quarto will see that the execution state matches the freeze file perfectly and will skip re-running the R code, completing your deployment in seconds.

## Passing Hugo shortcode to `.qmd`

Passing Hugo shortcodes through Quarto can be tricky because Quarto's underlying parser (Pandoc) often mistakes Hugo’s `{{</* shortcode */>}}` syntax for its own template expressions or markdown extensions. When this happens, it can garble the text or throw an execution error.


To pass Blowfish-specific shortcodes like buttons, badges, timelines, or galleries safely through a `.qmd` file, you need to use Quarto's Raw Markdown Blocks or Shortcode Escaping.

Here are the best ways to achieve this.

### Method 1: The Raw Attribute Block (Safest & Best)

The most foolproof method is wrapping the Hugo shortcode inside a raw markdown block targeted explicitly at Hugo's renderer (`hugo`). This completely hides the text from Quarto/Pandoc, ensuring it reaches your Blowfish theme untouched.


````html
```{=hugo}
{{</* shortcode_name */>}}
```
````

**Example: Adding a Blowfish Button & Badge**

To add a stylish Blowfish button and a colored badge to your bioinformatics workflow page, write it like this in your `.qmd`:

```html
### Pipeline Outputs

You can download the full differential expression matrix below:

```{=hugo}
{{</* button href="results/de_matrix.csv" target="_self" */>}}
  Download CSV Data
{{</* /button */>}}

{{</* badge color="success">*/>}}
  v1.2.0 Stable
{{</* /badge */>}}```
```


**Example: Adding a Blowfish Gallery**

Blowfish includes an amazing gallery shortcode for images. If your workflow generates multiple genomic plots and you want to display them in a Blowfish grid gallery:

````
### Visualizing Sample Clusterings

```{=hugo}
{{</*  gallery */>}}
  <img src="pca_plot.png" class="grid-w50" alt="PCA Plot" />
  <img src="volcano_plot.png" class="grid-w50" alt="Volcano Plot" />
{{</*  /gallery */>}}```
```
````

### Method 2: Inline Shortcode Escaping

If you want to use a shortcode directly inline inside a sentence (for example, placing a Blowfish icon next to a word), wrapping it in a large block is awkward. Instead, you can escape the shortcode brackets by doubling the opening and closing characters.

Quarto recognizes `{{{</* */>}}} `(three curly braces) as an escaped Hugo shortcode. It strips one set of braces during compilation and outputs a clean `{{</* */>}}`for Blowfish.

Example: Using Blowfish Icons Inline

Blowfish uses FontAwesome icons out of the box via its icon shortcode. To place a GitHub or DNA icon inside a sentence, format it like this:

```html
The complete source code for this alignment script is available on {{{</* icon "github" */>}}} GitHub. Please check the requirements before running.

Ensure your input data is in a valid {{{</* icon "dna" */>}}} FASTA format.
```
Summary Cheatsheet for Blowfish + Quarto

| Use Case                                                        | How to write it in your `.qmd `                       | 
|-----------------------------------------------------------------|-------------------------------------------------------|
| **Standalone Elements** (Buttons, Timelines, Galleries, Alerts) | Wrap inside a `{=hugo}` block.                          |
| **Inline Elements** (Icons, Badges inside text)                 | Wrap using triple braces: `{{{</* icon "name" */>}}}`.  |
| **Hugo variables** (e.g., `.Site.Params`)                       | Wrap inside a `{=hugo}` block.                          |

## Setup and Data Ingestion

First, we load the required libraries and simulate a gene expression matrix representing 100 high-yield target loci across a control and treatment cohort.

``` {r setup-and-load}
#| label: load-dependencies
#| message: false
#| warning: false

library(DESeq2)
library(ggplot2)

# Set seed for reproducible simulation
set.seed(42)

# Generate synthetic count data (100 genes, 6 samples)
cnts <- matrix(rnbinom(600, mu = 200, size = 1/0.1), ncol = 6)
rownames(cnts) <- paste0("GENE_", 1:100)
colnames(cnts) <- c("Ctrl_1", "Ctrl_2", "Ctrl_3", "Treat_1", "Treat_2", "Treat_3")

# Define experimental design
coldata <- data.frame(
  condition = factor(c("control", "control", "control", "treated", "treated", "treated")),
  row.names = colnames(cnts)
)

head(cnts)
```

## Differential Expression Analysis

We pass our matrix to `DESeq2`. This step is computationally isolated; thanks to our global `_quarto.yml` configuration, this heavy calculation is **frozen** on subsequent site deployments unless this specific file is altered.

``` {r deseq-execution}
#| label: run-deseq
#| message: false
#| warning: false
#| cache: true # Uses granular caching while actively modifying this file locally

dds <- DESeqDataSetFromMatrix(countData = cnts, colData = coldata, design = ~condition)
dds <- DESeq(dds)
res <- results(dds)

# Display top statistically significant hits
res_ordered <- res[order(res\$pvalue), ]
head(res_ordered, 3)
```

Follow these steps to set up your directory structure, configuration files, and a test post locally.

1. Project Directory Structure

Create a directory layout matching this exactly in your project root:

```
my-bio-site/
├── .github/
│   └── workflows/
│       └── deploy.yml
├── config/
│   └── _default/
│       └── hugo.toml
├── content/
│   └── workflows/
│       └── rna-seq/
│           └── index.qmd
├── themes/
│   └── blowfish/           <-- (Your Blowfish theme installation)
├── .gitignore
├── _quarto.yml
├── environment.yml
└── renv.lock
```

2. Environment Configurations

`environment.yml`

This file instructs Conda on how to provision system tools and the primary R engine on the GitHub runner.

```yaml
name: bio-env
channels:
  - conda-forge
  - bioconda
  - defaults
dependencies:
  - r-base=4.4.1
  - r-renv
  - r-rmarkdown
  - libxml2
  - openssl
```

`renv.lock`

Generate this file locally by opening R inside your repository and running:


```
renv::init()
renv::install(c("ggplot2")) # Put your required workflow R packages here
renv::snapshot()
```

`_quarto.yml`

This controls how Quarto converts files into Hugo-flavored Markdown.

```yaml
project:
  type: hugo
  render:
    - "content/workflows/"

format:
  hugo-md:
    keep-md: true
    html-math-method: mathjax
    code-fold: show

execute:
  freeze: auto
  cache: true
```

4. Git Ignore Rules

Add these explicit rules to your `.gitignore` to keep intermediate artifacts out of your commit logs while saving the frozen states:

```
public/
resources/
.Rproj.user/
.Rhistory
.RData
renv/library/
renv/staging/

# Ignore auto-generated Quarto output inside Hugo content folders
content/workflows/**/*.md
content/workflows/**/*_files/

# Crucial: DO NOT ignore your execution state cache
!_freeze/
```

5. The GitHub Actions Workflow File

Save this as `.github/workflows/deploy.yml`:

```yaml
name: Deploy Hugo site to Pages

on:
  push:
    branches: [ main ]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: "pages"
  cancel-in-progress: false

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4
        with:
          submodules: recursive
          fetch-depth: 0

      - name: Setup Pages
        uses: actions/configure-pages@v5

      - name: Setup Conda Environment
        uses: conda-incubator/setup-miniconda@v3
        with:
          mamba-version: "*"
          channels: conda-forge,bioconda,defaults
          auto-update-conda: true
          activate-environment: bio-env
          environment-file: environment.yml
          auto-activate-base: false

      - name: Cache R Packages
        uses: actions/cache@v4
        with:
          path: ~/.cache/R/renv
          key: ${{ runner.os }}-renv-${{ hashFiles('**/renv.lock') }}
          restore-keys: |
            ${{ runner.os }}-renv-

      - name: Restore R Packages via renv
        shell: bash -l {0}
        run: |
          Rscript -e "renv::restore()"

      - name: Setup Quarto
        uses: quarto-dev/quarto-actions/setup@v2

      - name: Setup Hugo
        uses: peaceiris/actions-hugo@v3
        with:
          hugo-version: '0.163.3'
          extended: true

      - name: Render Quarto Documents
        shell: bash -l {0}
        run: |
          quarto render content/

      - name: Build with Hugo
        env:
          HUGO_ENV: production
        run: |
          hugo --gc --minify

      - name: Upload artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: ./public

  deploy:
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    needs: build
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4
```

**Local Verification Step**

Before pushed to GitHub, confirm everything links locally by running these two commands in order via your terminal:

1. `quarto render content/` (Generates the hidden `_freeze/` folders and matching `.md` data)

2. `hugo server` (Compiles your Blowfish site locally so you can confirm styling looks perfect)
